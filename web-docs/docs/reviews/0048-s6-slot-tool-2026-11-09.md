# #48 S6 — `distro-builder slot`: the A/B slot tool, tested with real power loss (2026-11-09)

Status: **IMPLEMENTED AND OBSERVED ON REAL OVMF/KVM; NOT A PRODUCTION UPDATER.**
`release_acceptance` stays `false`. Follows
[the S7 matrix run](0048-s7-full-matrix-run-2026-11-08.md); ADR-0019 was
accepted on 2026-11-09 with "S6 must replace the image-level fixtures with a
tool that is power-loss tested while writing" as a carried-forward condition.
This is that tool.

## What it is

`distro-builder slot stage|arm|rollback|status`, Rust, in `tools/distro-builder`
(no daemon, no IPC). It edits Flowerly two-slot **disk images** (regular files;
it refuses block devices and symlinks). Block devices and a mounted ESP need a
privileged broker and are a later step.

| Command | Does | Never does |
| --- | --- | --- |
| `stage --slot root-b --candidate F --sha256 H` | writes the candidate into the inactive slot, `fsync` per MiB, re-reads and compares the SHA-256, then atomically replaces the manifest (temp + fsync + rename + fsync dir) | touch the ESP, the data partition or the active root |
| `arm --slot root-b --kernel K --initramfs I [--tries N] [--extra-option O]` | re-verifies the staged slot's hash, copies payload to the ESP, writes the entry as `flowerly-b+N.conf.tmp`, then publishes it with one FAT rename | write `loader.conf` (the builder now writes `default flowerly-*`), or claim success |
| `rollback --to root-a` | verifies the target slot, deletes the other slot's entries (and stray temps) | leave no bootable entry |
| `status [--witness F] [--verify-slots]` | lists entries (counting/good/bad), strays, slot identity; verdict `NO_BOOT_ENTRIES`, `NO_CANDIDATE`, `PENDING`, `FELL_BACK`, `FELL_BACK_UNCONFIRMED`, `FAILED_UNRESOLVED`, `ACTIVE`, `ACTIVE_UNCONFIRMED` | report `ACTIVE`/`FELL_BACK` without the guest's witness ledger |

Design points that the tests pin down:

- Slots are resolved from the manifest **bound to the real GPT** (checksummed
  header and entry array, names, PARTUUIDs, offsets, sizes); a caller-supplied
  offset is never used. Only the target slot's byte range can be written.
- The running root is a claim (`--active-partuuid`, default `root=` from
  `/proc/cmdline`); the tool refuses to touch it and re-verifies its hash.
- The durable *pending* record is the boot-counting entry itself, published by
  a single directory-entry rename. There is no second record to disagree after
  power loss. (Deviation from the step-1 plan, which had a ledger line: the
  ledger lives on the data partition the tool must never write.)
- Truncated witness records (no newline) are ignored, not trusted.
- Interruption points are compiled in only with `--features fault-injection`
  (never default): the binary then SIGKILLs itself at the point named in
  `FLOWERLY_SLOT_FAULT` (`stage:chunk:N`, `stage:before-readback`,
  `stage:before-manifest`, `stage:manifest-temp`, `stage:manifest-renamed`,
  `arm:after-payload`, `arm:after-tmp-entry`, `arm:after-rename`,
  `rollback:after-delete:N`).

## Tests

- 31 unit tests on an in-memory ESP: every refusal, every interruption point
  (partitions other than the target are byte-identical, the old manifest
  survives until the rename, re-running recovers), the verdict table, GPT
  parsing/corruption, write-range guard.
- CLI tests (`tests/slot_cli.rs`) run the real binary on a disk built by the
  real `build-flowerly-ab-disk.sh` with real mtools; with the feature, real
  SIGKILLs at each stage/arm/rollback step. CI provisions the tools and sets
  `FLOWERLY_REQUIRE_AB_TOOLS=1`, so these run instead of skipping.

Real-tool findings fixed while writing the tests: `mdir -b` prints directories
with a trailing slash and FAT names are case-insensitive (`/flowerly/b` shows
as `B`), which broke re-arming after a kill.

## Real OVMF/KVM run

Commit `5b670d61e5b82ef4e99a58a868d8254d2aef11bb`, same pipeline as the S7
runs; staging, arming, rollback and status all went through the tool.
Evidence: [evidence/0048-s6-5b670d6](evidence/0048-s6-5b670d6/) (JSON, 16 serial
logs, the witness ledgers the verdicts were computed from). Audit:
`INTERNALLY_CONSISTENT_NOT_RELEASE_ACCEPTED`, all 12 scenarios PASS, tool binary
bound by SHA-256 (`a88385f6086b97981d1d871fd858f2aac33eeb85cc822565638cf2cf1826cbcb`).

| After | Tool verdict (witness) | What really happened |
| --- | --- | --- |
| `unhealthy-b-3` | `FAILED_UNRESOLVED` (root-b) | tries exhausted but the last boot is still the failed B: not yet a fallback |
| `auto-fallback-a` | `FELL_BACK` (root-a) | loader returned to A |
| `healthy-b-1` | `ACTIVE` (root-b) | B blessed |
| `rollback-a` | `NO_CANDIDATE` (root-a) | B's entry removed |
| tool killed after payload / after tmp entry | `NO_CANDIDATE` (root-a); stray `.tmp` listed | loader booted A |
| tool killed after the rename | `ACTIVE` (root-b) | entry published, loader booted B, blessed |
| torn B entry, then A | `FELL_BACK` (root-a) | tries burned without a witness |

Stage of a 3 GiB slot: 13.7 s (was 31.2 s with the Python prototype). The
interrupted stage (killed at chunk 300) left ESP, root-a and data byte-identical,
the manifest untouched, the slot `MODIFIED`, and `arm` refused it
("has not been staged"); a tampered slot B was refused by `arm` and `status`.

Defects the real run found: the old Python stage did not mark the slot `ext4`
(the pipeline now stages with the Rust tool), and `debugfs` ignores the ext4
journal so the newest witness records were invisible after a SIGKILL; the
harness now replays the journal on a copy of the data partition before reading.

## Limits

- Image files only; no block device, no mounted ESP, no privileged broker, no
  signature verification of candidates (#49), no `flowerlyd` integration (Gate
  D). FAT directory updates are single-sector renames, not a journal.
- The torn-entry scenario still uses the Python fixture (it is external
  corruption, not tool behavior); clean-shutdown time is still `NOT_MEASURED`.
- Evidence is serial-log based and self-consistent, not cryptographic proof.
